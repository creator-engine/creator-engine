**Three-fix hardening batch: cwd-independent package-schema resolution, a
codex transcript-locator settle window, and a fail-closed reviewer
gh-identity guard.**

- **ce-ops#54 — schema paths resolve cwd-relative, breaking the v3 CLI
  outside the repo root.** `schema.py:load_schema` now anchors a package's own
  (non-absolute) schema name (`schemas/…`) to the package root via the
  established `Path(__file__).resolve().parents[2] / <rel>` anchor, so `ce` /
  `cev3` load their bundled schemas from ANY working directory, not only the
  repo root. A user-supplied relative `--answers-schema` stays cwd-relative —
  the resolver anchors only paths that resolve under the package `schemas/`.
  One loader fix; the ~50 `SCHEMA=` constants are untouched.
- **ce-ops#56 — the codex drive-bridge transcript locator races session-file
  creation, flaky `SpawnRefused` on an idle TUI.**
  `stamp_codex_transcript_locator` (`v3_seat_bridge.py`) now sleeps a bounded
  settle (`CODEX_TRANSCRIPT_SETTLE_S`, capped at the deadline) before its FIRST
  poll, killing the cold/idle-codex transcript-locator race (live-reproduced
  2026-06-13). Reuses the existing poll/timeout machinery.
- **ce-ops#58 — a reviewer venue could seed under the wrong gh-identity
  (#218 ambient wrong-identity leak).** `spawn_review_venue` gains a
  fail-closed step-2.5 guard: after `ce lane launch`, before `seed_brief`, it
  probes `gh api user --jq .login` through the `runner` seam — sourcing the
  SAME seat-env the review will, so it sees the review's identity by
  construction — and refuses (`mark_spawn_failed` + `SpawnRefused`, pane
  conserved, record value-free) when the venue login ≠ the envelope `actor`.
  The bridge keeps a LOCAL copy of the seat-env wrap script (it imports no v1
  module; `lane_runtime` is v1-classified), kept byte-identical by a
  drift-guard test.

The `validators/creator_engine_validator/**` edits require the wheel pair to be
rebuilt: `creator_engine_validator-0.2.0-py3-none-any.whl` is rebuilt from
current source (`setuptools.build_meta`) and `validators/wheelhouse/SHA256SUMS`
re-pinned to the rebuilt digest. `_version.py` is left untouched (the baked
`BUILD_GIT_SHA` is an ancestor of HEAD, so `verify_generated_version` stays
clean — no version bump).
