1. Executive Summary

▼

The CE dark factory is the end-state in which Creator Engine builds its own software autonomously. The Operator and controller co-frame ideas in natural language; the controller produces a ratified arc and tickets; governed seats pick up work units autonomously; local and forge-level automation handles PR mechanics and review assignment; the merge gate materializes committed intents — all without manual git operations by the Operator.

Operator's role at endgame: CEO-mode — ratify arcs, arm new authorities, handle escalations, hold root-key custody, manage external relationships. Every other delivery action is either autonomous (predicates hold) or queued in forge-visible AWAITING-OPERATOR state.

TARGET endgame picture:
  • Forge events spawn ephemeral NanoClaw controllers from content-addressed mandate pointers
  • Pickup conveyor feeds seats with ready tickets from the ratified arc
  • Containerized review daemon assigns reviewers and spawns review lanes automatically
  • Triage daemon processes seat-filed tickets via belt-feed polling
  • ce-queue-daemon (containerized singleton) is the merge gate AND Option A materializer
  • Host-ops broker mediates all host-level operations from contained contexts
  • Controllers themselves are contained and IaC-reprovisioned (T1 Aug 11 / T2 Aug 31)

Framing Guarantee: Governed Framing Without Explicit Verb

How CE guarantees governed framing without /ce frame

CE does not require users to type /ce frame. Governance attaches at the harness seam, not at a command parser.

  • Ring 0 (ce launch): scrubs ambient credentials, controlled environment
  • Ring 1 (ce launch): PreToolUse hook (.claude/hooks/ce-pretooluse.sh) registered BEFORE the harness starts
  • Ring 2: Stop hook for closeout evidence (Claude Code)

The PreToolUse hook fires on every tool call, validating path scope, work claim, reviewer authority, and role-shaped tool set. A seat receiving a brief cannot bypass this by omitting a command prefix.

For the persistent controller, ce takeover is the succession entry verb: it ingests evidence packets and reconstructs governance context, making framing a natural precondition of any subsequent action.

Doctrine: "Grader-outside-the-agent" (docs/architecture/stage-vocabulary.md). Intent recognition is soft (model-level). Enforcement is hard (harness boundary).

L4 — The Gate: Review → Approval → Merge Queue → Gate Daemon → Materializer

▼

4a: Review Assignment

Operator's question (c4): Local or forge level?

Answer: Hybrid — forge events trigger; local daemon decides and spawns.

  • FORGE Trigger + SSOT: GitHub PR-opened/PR-synchronized webhooks deliver the canonical event. Forge holds authoritative PR state (head SHA, author identity, required check results, CODEOWNERS).
  • DAEMON Decision + spawn: Local containerized review daemon applies the author/reviewer matrix, selects from CE_GATE_AUTHORIZED_REVIEWERS, mints a reviewer-authority envelope (single-use, short TTL), and spawns a local reviewer lane.

Why local, not forge: Reviewer spawn requires access to CE's internal seat registry, OpenBao-held authority, and reviewer-authority minting. These must not live in GitHub Actions (cannot hold approval-wall secrets there). Author ≠ reviewer is a CE hard invariant enforced locally.

References: playbooks/reviewer/, docs/delivery/REVIEW_GATE.md, docs/operations/GOVERNED_LANE_LAUNCH_PROTOCOL.md §0b

4b: Approval and Merge Queue

Approval wall: Queue daemon reads ce-kv/forge/approval-capability/wall#signing_secret from OpenBao to verify approval markers. Approval from authorized reviewer with required checks green triggers merge queue enqueue.

Merge queue: Ruleset ce-reference-protection-floor on main. Required: 1 review + required check (validate) + merge queue. Squash merge. Classic protection retired 2026-07-08. ce-materializer App 4244593 = sole always-bypass actor.

4. Answers to the Operator's Three Questions

▼

Q1: How does CE guarantee governed framing without an explicit /ce frame invocation?

CE does not require /ce frame. Governance attaches at the harness seam:

  1. ce launch --harness codex|claude is the canonical entry verb. The governed command builder wraps every seat launch with Ring 0 (credential scrub), Ring 1 (PreToolUse hook), Ring 2 (Stop hook).
  2. PreToolUse hook (.claude/hooks/ce-pretooluse.sh → hook_check.py) fires on EVERY tool call — validates path scope, work claim, reviewer-authority, role-shaped tool set. Seats cannot bypass this by omitting a prefix.
  3. For the persistent controller: ce takeover is the succession verb. It ingests evidence packets and reconstructs governance context, making framing a natural precondition of any subsequent action.

Soft intent recognition, hard enforcement: any phrasing can express intent. The harness boundary enforces what is allowed — grader-outside-the-agent (docs/architecture/stage-vocabulary.md).

Q2 (c4): Is reviewer assignment local or forge level?

Hybrid — forge events trigger; local daemon decides and spawns.

FORGE GitHub PR-opened/synchronized webhooks = canonical event trigger and SSOT for PR state (head SHA, author, check results, CODEOWNERS).

DAEMON Local containerized review daemon = assignment decision + reviewer spawn. Applies author≠reviewer matrix, selects from CE_GATE_AUTHORIZED_REVIEWERS, mints reviewer-authority envelope, spawns local lane.

Why local: Reviewer spawn needs OpenBao-held authority and approval-wall signing capability — cannot live in GitHub Actions. Author≠reviewer is a CE hard invariant enforced at the harness seam, not a forge ruleset.

References: playbooks/reviewer/, docs/delivery/REVIEW_GATE.md, docs/operations/GOVERNED_LANE_LAUNCH_PROTOCOL.md §0b

Q3 (c5): Is seat-filed ticket triage local or forge level?

Same hybrid — forge is SSOT for ticket state; triage decision is local.

FORGE GitHub issues in ce-ops = SSOT for issue state, labels, timestamps. CE's belt-feed polls GitHub Search API on schedule (30-min default) — durable default; push webhooks are premium.

DAEMON Local triage daemon = classification + queuing. Applies work-class inference (_infer_work_class, _infer_mutation_class), deduplicates against active arc and in-flight claims, queues for controller consideration.

Advisory only: Triage result does not ratify, approve, merge, or dispatch. Operator/controller ratifies queued items into the next arc.

References: ce-l3-triage-ready-queue-p0 (changelog v0.3.2), docs/design/ce-forge-side-automation.md import item 1, ce-belt-feed-polling-default-push-premium

Fail-Closed Patterns

  • Broker: missing label / unknown unit / symlink escape / path traversal = refused
  • Queue daemon: cannot write pre-mutation audit → returns failed, no mutation
  • Materializer: unprovable live ledger tail → HELD, no write
  • Gate daemon: cannot verify approval wall secret → refuses to process
  • PreToolUse hook: validation error → tool call blocked before execution

Kill Switches

  • Automerge: ce automerge-kill-switch off (v0.3.2)
  • Host-ops broker: broker-wide kill switch file in root-owned host config outside containers; per-verb disable flags
  • Materializer: ARMING_ENABLED=False hard invariant
  • Ephemeral listener: IaC-managed; disable by stopping webhook listener

  • Materializer HELD: .ce/state/brain-intent-materializer/held/<key>.json
  • Recursion bottom-out: AWAITING-OPERATOR in daemon state root
