Built for security with NVIDIA OpenShell

OpenShell isolates the runtime. Creator Engine governs the work.

Personal AI agents are heading to consumer machines. Runtime isolation keeps an agent contained — but isolation doesn't decide whether the work was right, what it cost, or whether a human approved it. That's a different layer, and it's the one we build. CE's boxed agents are built to run sandboxed on OpenShell, the open isolation layer — so consumer power never means free rein.

The runtime — OpenShell

Isolates & runs

An open, sandboxed place for a personal agent to execute, with local model routing. Contains the blast radius of a single run.

The work — Creator Engine

Governs & proves

How CE turns ideas into governed software

Five governed phases, one repo-visible trail. The same five words name every piece of work, from a one-line idea to a full feature — Frame → Shape → Build → Review → Ship — riding over a conserved governed state machine. Each phase lands a ratifiable artifact anyone can replay from the repository alone.

01

Frame

Understand the idea, the risk, and what done should mean before the agent acts.

02

Turn the idea into a Scope: Goal, Done-when, Budget, Change type, Ready.

03

Build

Run the agent inside the ratified envelope, with bounded authority and captured side effects.

04

Review

The grader lives outside the agent and checks evidence against the Done-when criteria.

05

Ship

Land a merged PR, delivered research, or ratified no-change with the trail intact.

Why consumer agents need governance

The safety gap is not theoretical.

If personal agents ship broadly without a governance layer, every laptop becomes a place where cost, files, secrets, and deploy authority blur into a chat permission. Creator Engine makes the boundaries explicit and replayable — and the difference is legible to anyone.

● Without governance — exposure

  • ✕ "Go ahead" becomes unlimited authority.
  • ✕ Runaway spend is discovered after the fact.
  • ✕ File and secret boundaries are implicit.
  • ✕ "Done" is whatever the agent claims in chat.
  • ✕ No durable trail joins intent, diff, evidence, and ratifier.

● With Creator Engine — governed

  • ✓ Budget is a fixed cap placed before Build.
  • ✓ Change-type decides how high the gate is.
  • ✓ External grading checks evidence, not transcripts.
  • ✓ Privileged changes require named human ratification.
  • ✓ The repo holds the trail: Scope, evidence, ledger, verdict.

Every consumer fear maps to a mechanism you can read in the repo.

A non-technical Creator should feel safe; a technical operator should believe the mechanism. Same safety, two altitudes.

The worry

"It'll spend a fortune looping."

The mechanism

A fixed Budget per Scope caps the run — can't outspend the cap.

The worry

"It'll change something dangerous."

The mechanism

Risk-tiered Change-type escalates deploy/secrets to the human gate.

The worry

"It'll leak my code or secrets."

The mechanism

Boxed isolation + a credential broker + a redaction gate — nothing leaks by default.

The worry

"How do I know it actually worked?"

The mechanism

An external grader checks Done-when — evidence, not the agent's say-so.

The worry

"What did it change, exactly?"

The mechanism

Every effect on a tamper-evident ledger — replayable from git clone.

The worry

"Who said it could ship?"

The mechanism

A named ratifier binds to the change — the privileged floor stays human.
