[gap] Egress broker missing read-lane: contained seats cannot read forge issues/PRs or do governed web research

## Symptom
Contained seats (dev-3 `ce-vps-codex`, dev-4 `ce-dgx-codex`) have no brokered lane for GitHub API
**reads** (issue/PR body, comments) or governed web research. The egress-broker verb set covers
only write-side forge operations (self-push, self-review). As a result: no `gh` or `curl` inside
runsc/gVisor containers → API calls fail 404 or are blocked; no web-fetch → research-class units
cannot be routed to contained seats at all.

## Root cause
Broker verb set was built for the self-push/self-review write path (ce-ops#242/#265/#267/#268/
#289). Broker socket /run/ce-egress/<seat>.sock (tools/egress-broker/) has no forge-read verbs
and no governed web-fetch verb. Seats needing either must carry credentials (violates #228) or
run uncontained.

## Proposed shape
Extend the broker verb set with read-only forge verbs minted against the same short-TTL scoped
tokens as the write path: get-issue / get-pr / list-comments (JSON). Properties: read-only scope;
rate-capped per seat broker-side; audited per call; app-auth two-lane parity (kind:broker fleet
lane AND kind:own solo lane — for THIS slice implement kind:broker, leave a documented seam +
test stub for kind:own). Web-fetch verb: OUT OF SCOPE this slice.
