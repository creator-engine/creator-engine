CONTEXT: The contained seat reaches the egress brokers via a bind-mounted Unix socket. The broker daemons (`ce-egress-broker-dev3.service`, `ce-egress-self-review-dev3.service`) unlink+re-create their socket files on restart, rotating the inode. The container bind-mount is frozen to the inode at container-launch time, so after ANY daemon restart the seat connects to a dead inode → persistent ECONNREFUSED (perms are correct `srw-rw---- root ce-dev-3`; EACCES is NOT the issue). Evidence: host live sockets inode 190084/190085 healthy (ss -lx LISTEN), container bind-mount sees inode 1 (stale). This BLOCKS the fleet switch (dev-1/dev-4 onto self-push); the interim relaunch-after-daemons-stable works only until the next daemon restart. Relates: ce-ops#282, ce-ops#270.
DURABLE FIX (systemd socket-activation — the inode-stable solution):
1. Add `.socket` units (e.g. `ce-egress-broker-dev3.socket` + `ce-egress-self-review-dev3.socket`) that create+own `/run/ce-egress/dev-3.sock` and `dev-3-review.sock`; systemd/kernel owns the inode for the unit lifetime → inode stable across daemon restarts.
2. Service units `Requires=`+`After=` the socket units; REMOVE the `bind()`/`unlink()` from the broker Python and inherit the listening fd via `SD_LISTEN_FDS` (`socket.fromfd(...)`).
3. Container bind-mount then stays valid indefinitely across daemon restarts.
DO NOT use SO_REUSEADDR+skip-unlink (a restarted listener still needs to unlink or hits EADDRINUSE) — socket-activation is the correct fix.
