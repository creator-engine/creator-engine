# Conveyor Intake Queue

The conveyor intake queue is a local, file-backed list of controller-declared ticket units. It lives by default under `.ce/state/conveyor-daemon/intake-queue/`, or under `CE_CONVEYOR_INTAKE_QUEUE_ROOT` when configured. Its state directories are `pending/`, `claimed/`, and `done/`; lower numeric priorities sort first in filenames of the form `{priority:05d}-{unit_id}.yaml`.

Each unit pins its dispatch brief with `brief_ref` and a 40- or 64-hex lowercase `brief_sha`, and declares its allowed `territory_paths`. These values are value-free metadata: no credentials are stored in a unit, and a queue claim grants no authority beyond that already held by the claimer. A successful claim carries an opaque 256-bit ownership token only in its local claimed record; it is cleared before the unit returns to `pending`.

`stock` (also `publish_entry`) puts a unit in `pending/`. Publication and lifecycle lookup share the immutable `unit_id` lock, rather than a priority-prefixed filename: identical JSON/YAML replays while pending are idempotent, while any claimed, launching, done, divergent, or split lifecycle record is refused and never overwritten. `claim_entry(claimer, ttl_seconds=...)` accepts only finite TTLs in `0 < t <= 3600` before its rename, moves an entry to `claimed/`, and records owner, token, generation, and expiry; legacy `claim_next()` remains available as a no-expiry controller claim. `fence_launch` requires the matching owner/token and a live finite TTL, then atomically changes the record to non-reclaimable `launching` before an external launcher runs. `release_entry` returns an owned claim to `pending/` and clears claim fields. `complete_entry` requires the owning claimer, exact opaque claim token, and exact generation before it moves an entry to `done/`; legacy `mark_done` remains its no-claimer compatibility wrapper. Failed write/move transitions report bounded `IntakeTransitionError` evidence and restore their prior durable ownership record when possible.

Before claiming pending work, the queue repairs its own unambiguous crash windows: a `pending` or `done` payload stranded in `claimed/` after its durable state write but before its location rename is moved to its matching directory under the same stable per-entry lock. A conflicting recovery destination or any other incompatible claimed location/state is refused rather than guessed at. It then scans claimed records for expired claims, clears their claim fields, atomically returns them to `pending/`, and records a stale reclaim. Each claim, reclaim, launch fence, release, and completion for a claim file shares one stable POSIX lock boundary, so a stale reclaimer cannot apply an earlier read after a launch state transition. Record replacements and inter-directory moves sync their containing directories before success is reported. A `launching` record is deliberately not reclaimed: an unknown launcher outcome must be reconciled rather than retried into a duplicate seat. The move from `pending/` to `claimed/` uses POSIX `os.replace`, so concurrent claimers have exactly one winner; a losing rename observes `FileNotFoundError` and continues scanning.

Priorities are non-negative integers and claim/list selection is numeric with filename tie-breaking. The legacy minimum-width filename remains readable, including six-digit priorities. If a record replacement completes but its containing-directory fsync reports failure, claim placement re-reads the authoritative claimed path: an intact claimed payload remains claimed rather than being returned to `pending` or stranded under an ambiguous status.

Every claim, release, completion, and stale reclaim best-effort appends an NDJSON record to `intake-claims.jsonl` at the queue root. Records include `action`, `unit_id`, `claimer`, `brief_sha`, and `ts`. Ledger I/O failure is reported to stderr but never aborts the associated lifecycle operation; the ledger is append-only and is never truncated.

`conveyor_seat_pull.SeatPullAdapter` is the library-level seat handoff seam. It atomically claims one unit, accepts only a 64-hex SHA-256 pin for launch, validates canonical branch/worktree/work-class/territory metadata, and opens the relative brief descriptor-by-descriptor below a supplied trusted root without symlinks or escape. It hashes those opened bytes and writes an adapter-owned, content-addressed read-only snapshot for the launcher.

Before fencing launch, the adapter reads a controller-owned evidence record at `controller-evidence/<unit-id>.json`. That record is not a parallel claim: it is a snapshot of the existing normal `work_claims` marker API plus the controller's territory check. The adapter requires it to bind the unit, seat, controller identity, exact brief digest, canonical territory digest and paths; it rejects released, stale, malformed, foreign, or colliding work-claim evidence. It publishes its content-addressed brief snapshot by syncing a private temporary file and atomically linking its final name, so observers never read a partial final; safe private crash residue is removed and an old corrupt final is replaced only after identity-safe verification. It then fences the queue ownership and passes a no-follow, directory-descriptor-anchored snapshot handle plus declared lane metadata to the governed launcher. The launcher must consume the snapshot through that handle during the invocation; replacement before consumption fails closed, and the adapter closes the handle on every pre-launch refusal and on launcher return. A verification, fence-transition, or definite launcher refusal releases the owned claim. A launcher exception retains the fenced claim because the launch outcome is unknown and retry would risk duplication.

The feature remains gated by `CE_CONVEYOR_INTAKE_ENABLED=1`; absent that flag, daemon behavior is unchanged. This queue substrate does not send pane text, write sockets, launch seat subprocesses, or grant any new authority.
