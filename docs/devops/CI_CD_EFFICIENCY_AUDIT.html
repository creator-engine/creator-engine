CE CI Efficiency Audit: Preserve Safety, Remove Fidelity Drift

Creator Engine's local and CI validation share substantial safety coverage, but their orchestration and PR-data inputs diverge. The practical sequence is to measure gates, consolidate shared definitions, and ratify any change that can weaken a safety property.

Timing limitation: trustworthy live CI timing telemetry was unavailable for this audit. The documented full-suite range (about 1–4 minutes) and check-examples range (about 60–90 seconds) are documentation, not measurements.

Validation pipeline

  1. Author carrier / local inputdeclared work class, scope, paths
  2. Local base + head preflightce validate-pr
  3. Pushcandidate branch
  4. CI live PR metadata + baseserver-resolved comparison
  5. Required PR gatestests, sizing, coupling, manifest
  6. Merge groupcombined candidate validation

The current fidelity gap

Local preflight derives the work class and coupling exemption from carrier/local input. CI evaluates the live PR body and a server-resolved comparison base. This creates two sources of truth: a carrier can be locally coherent while the PR body is stale or otherwise different. The current-main #557 history demonstrated declared-class corrections from story to feature and then epic; the execution fixes landed, but the structural carrier-versus-PR-body split remains.

Local baseline comparison also has a distinct policy: it carries identical baseline/head failure IDs. That protects authors from inherited failures, but without freshness or identity constraints a long-lived failure can be silently normalized. These are fidelity and safety design questions, not evidence that any present gate should be removed.

Ranked recommendations

1. Safe quick win: one machine-readable gate manifest

Generate a shared ordered gate manifest consumed by the workflow and pr_preflight.py. A parity test should fail when gate IDs or PR-data sources diverge.

2. Safe quick win: one declared-work-class payload

Generate the payload from the carrier, then submit and verify it against the live PR body. A mismatch should fail locally before push and in CI with the same error code.

3. Safe quick win: publish timing evidence

Record per-gate duration, cache status, test count, and comparison-base SHA as CI artifacts. Use a secret-safe schema so a sequence of runs can establish p50 and p95.

4. Safe quick win with benchmark guard: remove duplicate example sweeping

Reuse one recorded aggregate check-examples result only after malformed and well-formed negative coverage proves every present property remains covered.

5. Design / ratification: bound carried baseline failures

Replace unconstrained failure-ID parity with an explicit dated allowlist keyed to test node and base SHA. Expiry or node/SHA changes must fail closed.

6. Design / ratification: introduce path-aware local tiers

Always run carrier, class, confidentiality, and permissions checks locally; keep the full suite before merge and define escalation for validator/runtime surfaces. Seeded mutations must demonstrate no lost safety property.

7. Design / ratification: verify merge-group combined diffs

Add merge-group checks for manifest, sizing, and coupling—or prove PR-only sufficiency. A fixture with conflicting individually-green PRs should be rejected.

Risks and open questions

  • Live Actions logs and timing data were not available to this read-only audit; instrument before claiming latency savings.
  • Tiering and baseline changes can weaken safety unless negative tests and ratification accompany them.
  • Current-main conclusions were anchored to the audited origin/main evidence; re-check the gate manifest as workflows evolve.
